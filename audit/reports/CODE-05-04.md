# CODE-05-04 — `POST /api/repertoire/seed` returns JSON `null`; the frontend button throws — and the route has zero test coverage
- **Severity:** high
- **Type:** wrong-result
- **File:** `backend/repertoire.py`
- **Line(s):** 1865-1911 (missing return); consumer at `frontend/repertoire_builder.js:540-550`; route at `backend/api.py:965-970`
- **Component:** Repertoire / API contract
- **Repro script:** `audit/scripts/CODE-05_repro_seed_contract.py`
- **Detected by:** CODE-5

## Expected
`seed_default_repertoires()` returns a status dict on every path (as it already does on the guard path), the endpoint serialises it, and the frontend's `data.status === 'ok'` check is satisfied so the user gets the "Default repertoires seeded successfully!" confirmation.

## Actual
`backend/repertoire.py:1865-1911` has **no `return` statement on the success path**. The `for` loops at 1887-1911 fall off the end of the function, so it evaluates to `None`. FastAPI therefore serialises the body as the JSON literal `null`:

```
--- A) guard path: no force, repertoire non-empty ---
   HTTP 200 body: {"status":"skipped","message":"Repertoire already contains moves. Seeding skipped to protect user data."}

--- B) SUCCESS path: force=true on a cleared repertoire ---
   HTTP 200 body: 'null'
   moves actually seeded: 72
   frontend check `data.status === 'ok'` would evaluate data == None

--- C) replay the exact frontend code path ---
   FRONTEND CRASHES: AttributeError: 'NoneType' object has no attribute 'status'
   (caught by repertoire_builder.js:548 catch -> console.error only)

--- D) direct call returns None? ---
   seed_default_repertoires(force=True) -> None
```

So the button **does** seed 72 moves and **does** report success to nobody. `frontend/repertoire_builder.js:542-550`:

```javascript
const res = await fetch('/api/repertoire/seed', { method: 'POST' });
const data = await res.json();
if (data.status === 'ok') {          // <-- data is null here
    alert("Default repertoires seeded successfully! ...");
    await this.loadRepertoire(this.activeColor);
}
} catch (e) {
    console.error('Error seeding defaults:', e);   // <-- swallowed
}
```

The button's own tooltip is also wrong — `frontend/index.html:92`:
> `title="Reset and seed Italian Game, Sicilian Dragon, and King's Indian"`

It resets nothing: the frontend never sends `force=true`, so on a non-empty repertoire the endpoint returns `{"status":"skipped",…}` (which the frontend also ignores, since it only checks for `'ok'`), and the button is a silent no-op.

## Root cause
Missing `return` on the success path of `seed_default_repertoires` (`backend/repertoire.py:1911` is the last statement of the function body), combined with a frontend that treats a falsy/absent body as success and wraps the failure in a `console.error`-only `catch`.

Nothing catches this because the route is **completely untested**:
```
$ grep -rho "/api/repertoire/seed" tests/test_*.py | wc -l
0
```
