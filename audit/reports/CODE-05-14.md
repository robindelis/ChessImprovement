## Root cause
Features were replaced without removing their routes, and no contract test enumerates `app.routes` against the frontend's fetch list. `AGENTS.md` §3 lists `app.js` as "Global routing, tab switching, user badge, settings form" — there is no dashboard tab, which is why the endpoint has no consumer; the doc never claims there is one, so this is a silent dead subsystem rather than documented drift.

## Exploit / escalation
1. `POST /api/train/evaluate_move` (`backend/api.py:629`) is an unauthenticated endpoint that runs a Stockfish evaluation on a caller-supplied FEN and move and writes drill state — a dead route with zero tests is exactly the surface a future change regresses unnoticed.
2. `GET /api/blunders/{blunder_id}` (`:537`) does 4 queries and returns `refutation_line` / `best_line` / `continuation_pv` assembled from `refutation_pv`; with no test, a change to that parsing ships silently.
3. Adjacent variants with the same root cause (assert-on-presence instead of assert-on-value):
   - `tests/test_api.py:45-50` `test_repertoire_tree` asserts only `coverage_pct` and `total_moves` exist — never their values, so the `min(100.0, max(0.0, …))` clamp at `backend/repertoire.py:1287` is untested.
   - `tests/test_api.py:52-56` `test_repertoire_explore` asserts only `assertIn("moves", data)` on a **network** response; the eleven other documented fields (`white_total`, `draws_total`, `black_total`, `user_games_total`, per-move `my_stats`, `threat_score`) are only checked in `tests/test_repertoire.py:135-141`.
   - `tests/test_api.py:15-20` `test_account_endpoint` asserts only `connected` and `username` exist, never that `has_token` is a bool.
