# CODE-02-16 — SSE streams emit `data: {"error": "<raw exception>"}` with no event type, so a crashed engine silently freezes the eval bar
- **Severity:** medium
- **Type:** wrong-result
- **File:** `backend/evaluator.py`
- **Line(s):** 106-113, 196-216
- **Component:** `GET /api/repertoire/eval_stream`
- **Repro script:** `audit/scripts/CODE-2_sse_contract.py`
- **Detected by:** CODE-2

## Expected
An SSE protocol needs a discriminating field (`event:` name, or a stable `type` key) so the
client can distinguish progress from terminal failure. Terminal errors should also be
logged server-side.

## Actual
`stream_eval` has three failure exits, and all three write a bare `data:` frame with an
`error` key and no event name:

```python
# backend/evaluator.py:106-113
try:
    board = chess.Board(fen)
    if not board.is_valid():
        yield f"data: {json.dumps({'error': 'Invalid FEN'})}\n\n"
        return
except Exception:
    yield f"data: {json.dumps({'error': 'Invalid FEN'})}\n\n"
    return
```

```python
# backend/evaluator.py:208-216
except Exception as e:
    # Engine crashed or UCI protocol error - reset engine
    if self._engine:
        try:
            await self._engine.quit()
        except Exception:
            pass
        self._engine = None
    yield f"data: {json.dumps({'error': str(e)})}\n\n"
```

`str(e)` on line 216 is the raw exception text — a `chess.engine.EngineTerminatedError`,
a `FileNotFoundError` naming the full Stockfish path, or a `TimeoutError` from
`asyncio.wait_for(..., timeout=2.0)` at `evaluator.py:56` is shipped to the browser.
Nothing is logged.

The consumer silently drops it. The Repertoire Builder gates on a `score_cp` key:

```js
// frontend/repertoire_builder.js:1777-1781
const data = JSON.parse(trimmed.slice(6));
if (data.score_cp !== undefined) {
    this.renderEvalBar(data.score_cp, data.mate, data.depth);
    this.evalCache.set(fen, data);
}
```

and the Scout's reader does not even look at `score_cp` — it passes `data.eval`
(`frontend/scout.js:1950`), which is never emitted, so *both* consumers drop the error
frame (see CODE-02-23 for the full key mismatch). The eval bar simply stops updating
mid-navigation with no user-visible indication that anything failed.

Two secondary contract problems in the same generator:

- **No terminal frame on disconnect.** The early exits at `evaluator.py:103-104` and
  `151-152` (`if request and await request.is_disconnected(): return`) produce **zero**
  frames — not even a terminal `final` frame. A client that disconnects mid-search and
  reconnects gets no indication the stream ended.
- **The `final` flag never arrives after a mid-search disconnect.** `break` at
  `evaluator.py:167` exits the `async for`, `last_res` holds the last emitted depth
  (e.g. 6), and because `6 < max_depth` nothing is cached — correct — but no terminal
  frame is sent either, so the frontend keeps the last non-final frame on screen forever.

## Root cause
The SSE protocol was designed for the happy path only. There is no discriminated union, no
`event:` name, and no `finally` that emits a terminal frame.

## Exploit / escalation
1. Move `bin/stockfish/stockfish-linux-x86-64-universal` away while the app is open → every
   subsequent `eval_stream` yields `{"error": "Stockfish binary not found at /home/robin/…"}`
   (full absolute path disclosed) and the UI shows a frozen bar with no error.
2. Corrupt the engine mid-search (e.g. `kill -9`) → the frame is
   `{"error": "EngineTerminatedError(...)"}` and the singleton is torn down
   (`evaluator.py:208-215`); the next request respawns it, so the user sees a *silent*
   ~1 s stall rather than a message.
3. Adjacent: `evaluator.py:171-175` converts a mate score to a flat `±10000`, discarding
   the mate distance, so `M1` and `M9` render identically on the eval bar unless the
   frontend's separate `mate` field is used — it is (`repertoire_builder.js:1707`), so
   this is cosmetic, but the two representations of the same fact can disagree.
