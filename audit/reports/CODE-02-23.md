# CODE-02-23 — `/api/repertoire/eval_stream` emits `score_cp`, but the Scout's eval-bar consumer reads `data.eval` — the Scout eval bar is permanently stuck at `+0.0`
- **Severity:** high
- **Type:** wrong-result
- **File:** `backend/evaluator.py` (producer), `frontend/scout.js:1950` (consumer)
- **Line(s):** evaluator.py:118-126, 130-139, 181-189 (producer); scout.js:1930-1960 (consumer)
- **Component:** `GET /api/repertoire/eval_stream` ↔ Opening Scout eval bar
- **Repro script:** `audit/scripts/CODE-2_sse_contract.py`
- **Detected by:** CODE-2

## Expected
The SSE payload's centipawn field name must match what every consumer reads. The
Repertoire Builder consumer and the Scout consumer must agree.

## Actual
Every frame the backend emits uses the key **`score_cp`**:

```python
# backend/evaluator.py:181-189
last_res = {
    "depth": depth,
    "score_cp": score_cp,
    "mate": mate,
    "best_move": best_move_uci,
    "best_san": best_move_san,
    "final": (depth >= max_depth)
}
yield f"data: {json.dumps(last_res)}\n\n"
```

so do the three terminal frames (`evaluator.py:118-126` checkmate, `130-139`
stalemate/insufficient, `109`/`112` invalid FEN — the last two use `error`).

The Repertoire Builder consumer matches:

```js
// frontend/repertoire_builder.js:1777-1781
const data = JSON.parse(trimmed.slice(6));
if (data.score_cp !== undefined) {
    this.renderEvalBar(data.score_cp, data.mate, data.depth);
    this.evalCache.set(fen, data);
}
```

The Scout consumer does **not** — it reads a key the endpoint never emits:

```js
// frontend/scout.js:1948-1951
const data = JSON.parse(eventLine.slice(6));
this._updateEvalBar(data.eval, data.mate);
```

```js
// frontend/scout.js:1961-1986
_updateEvalBar(scoreCp, mate) {
    ...
    let evalText = '+0.0';
    let pct = 50;

    if (mate !== null && mate !== undefined) {
        evalText = `M${Math.abs(mate)}`;
        pct = mate > 0 ? 100 : 0;
        barLabel.className = ...
    } else if (scoreCp !== null && scoreCp !== undefined) {
        ...
    }
    ...
}
```

`grep -rn "_updateEvalBar" frontend/scout.js` → exactly two hits (the call at 1950 and the
definition at 1961), so the SSE reader is its **only** caller. `data.eval` is `undefined`
on every frame; the `else if` guard `undefined !== undefined` is false; `evalText` and
`pct` keep their `'+0.0'` / `50` initialisers and no label class is applied.

The literal string `"eval"` *is* used as a JSON key elsewhere in the backend — but only in
the **explorer** payloads (`repertoire.py:321`, `repertoire.py:384`,
`db.py:221-222`), which come from `GET /api/repertoire/explore`, not from the SSE stream.
The two key conventions coexist in the same codebase with nothing reconciling them.

The only way the Scout bar shows anything is the checkmate terminal frame, where
`mate` is present and the `if` branch fires:

```python
# backend/evaluator.py:118-126
res = {"depth": 99, "score_cp": -10000 if board.turn == chess.WHITE else 10000,
       "mate": score_mate, "best_move": "", "best_san": "", "final": True}
```

## Root cause
The SSE DTO field name was changed (or the Scout consumer was written against a different
payload) with no shared contract, no `response_model`/Pydantic schema on the stream, and
no TypeScript/interface to catch the mismatch — the project is zero-build vanilla JS, so
the only contract enforcement is the human reader.

## Exploit / escalation
1. Any non-terminal position opened in the Scout tab shows a permanently balanced eval bar
   reading `+0.0` at 50 %, with no `white-winning`/`black-winning`/`equal` label class.
   The user has no indication the engine is even running.
2. Adjacent: `frontend/scout.js:1987-1989` then flips the height for a black-oriented
   board *after* the label class was already computed from the unflipped value:
   ```js
   if (this.orientation === 'black') {
       pct = 100 - pct;
   }
   ```
   so even once the key name is fixed, the Scout bar's label and height will contradict
   each other in black orientation.
3. Adjacent: `frontend/repertoire_builder.js:1741` short-circuits on
   `if (cached.depth >= 14) return;` while the request is issued with `depth=16` — a
   hardcoded threshold that silently downgrades the requested search depth to 14 on a
   cache hit. This is the same "no contract" family of defect.
