# CODE-02-10 — The schema contains no indexes at all, despite every hot query filtering/ordering on unindexed columns
- **Severity:** medium
- **Type:** spec-violation (perf)
- **File:** `backend/db.py`
- **Line(s):** 24-208 (all `CREATE TABLE` statements); consumers in `backend/api.py`
- **Component:** SQLite schema
- **Repro script:** `audit/scripts/CODE-2_repro.py` (PROBE 5)
- **Detected by:** CODE-2

## Expected
Every column used in a `WHERE`, `ORDER BY`, `GROUP BY` or `JOIN ... ON` predicate that is
not already the left-most column of some index should have one.

## Actual
`grep -rn "CREATE INDEX" --include=*.py .` returns **zero** hits. The only indexes that
exist anywhere are the implicit ones from `PRIMARY KEY` and the two `UNIQUE(...)` table
constraints (`repertoire_moves`, `repertoire_studies`) and `scouted_content.source_id`.

Unindexed columns that are actively filtered, ordered or grouped on:

| Column | Used at | Query |
|---|---|---|
| `games.played_at` | `api.py:312` | `ORDER BY played_at DESC LIMIT ? OFFSET ?` |
| `games.user_color` | `api.py:297` | `WHERE user_color = ?` |
| `blunders.game_id` | `api.py:502, 469, 546` | `JOIN games g ON b.game_id = g.id` (FK, unindexed) |
| `blunders.cpl_loss` | `api.py:521` | `ORDER BY b.cpl_loss DESC LIMIT ?` |
| `blunders.opening_name, color` | `api.py:452-458` | `GROUP BY opening_name, color` |
| `blunders.created_at` | `api.py:470` | `ORDER BY b.created_at DESC LIMIT 5` |
| `blunders.eco` | `api.py:512` | `AND b.eco LIKE ?` (prefix — indexable) |
| `drill_reviews.next_review_date` | `api.py:448, 618` | `WHERE next_review_date <= ?` |
| `scouted_at` | `db.py:478` | `ORDER BY scouted_at DESC` |
| `study_moves(repertoire, parent_fen, move_uci)` | `db.py:330, 312, 316` | see CODE-02-08 |
| `blunders(game_id, ply)` | — | **no UNIQUE**, so duplicate blunders are possible |

The most consequential is `blunders.game_id`: every read of blunders joins to `games`
through it, and it is a declared-but-unenforced foreign key (`FOREIGN KEY(game_id)
REFERENCES games(id)`, `db.py:82`) — which, per CODE-02-20, is inert because
`PRAGMA foreign_keys` is never enabled.

## Root cause
Schema was written once and never revisited; migrations only ever `ADD COLUMN`. There is no
`ANALYZE`, no `PRAGMA optimize`, and no index maintenance on a database that is
append-heavy (`explorer_cache` and `blunders` are the fastest-growing tables).

## Exploit / escalation
1. `GET /api/games/recent?limit=100&search=...` on a DB with tens of thousands of games
   forces a full `games` scan + sort for every keystroke of the search box.
2. `GET /api/repertoire/game_gaps` (the main "BIGGEST BLUNDER" feature) and
   `GET /api/dashboard` both scan + group the entire `blunders` table.
3. Adjacent: the *absence* of `UNIQUE(game_id, ply)` on `blunders` is what allows the
   duplicate-blunder path in CODE-02-04 to actually duplicate rows.
