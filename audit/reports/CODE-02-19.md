# CODE-02-19 — `lichess_client`: the 429 retry leaks the first response, there is no second retry, the NDJSON stream is read unbounded into memory, and every failure becomes `[]`
- **Severity:** medium
- **Type:** spec-violation / resource leak
- **File:** `backend/lichess_client.py`
- **Line(s):** 60-99
- **Component:** Lichess NDJSON game fetch
- **Repro script:** n/a (static read)
- **Detected by:** CODE-2

## Expected
A retry should close the previous response; retries should be bounded with backoff and
cover repeated 429s; a streaming download should be consumed incrementally with a cap;
and transport failures should be distinguishable from "no games".

## Actual
```python
# backend/lichess_client.py:79-99
resp = requests.get(url, params=params, headers=headers, stream=True, timeout=60)
if resp.status_code == 429:
    print("Lichess rate limit hit (429). Waiting 3 seconds...")
    time.sleep(3)
    resp = requests.get(url, params=params, headers=headers, stream=True, timeout=30)

if resp.status_code != 200:
    print(f"Failed to fetch games: status {resp.status_code} - {resp.text[:150]}")
    return []

for line in resp.iter_lines(decode_unicode=True):
    if line:
        try:
            g = json.loads(line)
            games.append(g)
        except json.JSONDecodeError:
            continue
except Exception as e:
    print(f"Exception during games fetch: {e}")

return games
```

Defects:

1. **Leaked response on retry.** The first `resp` is a `stream=True` response whose
   connection is still held; it is reassigned to `resp` without `.close()`. The socket (and
   its file descriptor) is not returned to the pool until GC. Under repeated 429s this
   accumulates.
2. **Single retry, fixed 3 s, no jitter, no backoff, and the retry's status is not
   re-checked for 429.** A second 429 falls into the `!= 200` branch and returns `[]`.
3. **Unbounded read.** With `max_games` unset the request omits the `max` param
   (`lichess_client.py:69-70`) and the entire account history is streamed into a Python
   list. `POST /api/repertoire/sync_games` (the default `max_games=None`,
   `api.py:1014`) and `stream_analyze_user_games` (`api.py:1022`) both use the default, so
   a full-history sync materialises every game (with `moves=true`) in memory.
4. **`timeout=60` is a per-read-chunk timeout, not a total timeout.** A server that
   dribbles one byte every 59 s keeps the request open indefinitely. There is no overall
   deadline and no `resp.close()` in a `finally`.
5. **All failures collapse to `[]`.** 401, 429, 5xx, a `ConnectionError`, and a genuinely
   empty result are indistinguishable, which is what makes CODE-02-11's fake-success
   unavoidable. The only diagnostic is a `print` to stdout — the Electron shell spawns
   Python with piped stdio, so these lines are usually discarded.
6. **Mid-stream truncation is silent.** The `except Exception` at line 96 wraps the
   `for line in resp.iter_lines(...)` loop, so a network drop mid-stream returns a
   **silently truncated** list that the caller treats as a complete set of games.

## Root cause
`[]` is overloaded to mean three different outcomes, and there is no `response` context
manager, no retry policy, and no streaming budget.

## Exploit / escalation
1. `POST /api/repertoire/sync_games` with no `max_games` on an account with thousands of
   games → multi-hundred-MB list plus a multi-hundred-MB JSON blob per entry, all inside
   the request thread.
2. A mid-stream truncation (server closes, proxy timeout) yields a *partial* game list that
   `stream_analyze_user_games` then analyses to completion and reports as
   `"total_games": len(games)` — the UI reports a successful partial sync.
3. Adjacent: the Lichess token is sent in the `Authorization` header
   (`lichess_client.py:13-17`), and `self.headers` (which contains the token) is passed to
   `get_opening_explorer_stats` (`lichess_client.py:109`) against
   `explorer.lichess.org`. The token is not needed for the public explorer and is
   therefore disclosed to a third-party host on every `GET /api/blunders/{id}` call.
4. Token sourcing (`lichess_client.py:19-39`) scans `.env` for the first line containing
   `lip_`, returning the first `KEY=lip_…` match with no validation — a commented-out
   example or an expired token earlier in the file wins over the live one.
