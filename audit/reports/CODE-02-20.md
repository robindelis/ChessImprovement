# CODE-02-20 — Schema/doc drift: `AGENTS.md` §5 documents 5 tables (code has 9), omits 7 real `blunders` columns, and `PRAGMA foreign_keys` is never enabled so every declared FK is inert
- **Severity:** medium
- **Type:** spec-violation
- **File:** `backend/db.py`, `AGENTS.md`
- **Line(s):** db.py:24-208 (all DDL), 82/105/177 (FKs); AGENTS.md:148-194
- **Component:** Database schema / documentation
- **Repro script:** `audit/scripts/CODE-2_freshdb.py`
- **Detected by:** CODE-2

## Expected
`AGENTS.md` §5 is declared "the authoritative architecture doc" (`BRIEF.md:13`) and should
be an accurate mirror of `init_db()`.

## Actual
**(a) Four undocumented tables.** `AGENTS.md` §5 documents `games`, `blunders`,
`repertoire_moves`, `explorer_cache`, `scouted_content`. `init_db()` also creates:

```python
# backend/db.py:29-34
CREATE TABLE IF NOT EXISTS settings (key TEXT PRIMARY KEY, value TEXT)
# backend/db.py:94-107
CREATE TABLE IF NOT EXISTS drill_reviews (id INTEGER PRIMARY KEY AUTOINCREMENT, blunder_id INTEGER UNIQUE, ...)
# backend/db.py:157-167
CREATE TABLE IF NOT EXISTS repertoire_studies (id INTEGER PRIMARY KEY AUTOINCREMENT, name TEXT NOT NULL, repertoire TEXT NOT NULL, description TEXT DEFAULT '', created_at INTEGER, updated_at INTEGER, UNIQUE(name, repertoire))
# backend/db.py:170-179
CREATE TABLE IF NOT EXISTS study_moves (study_id INTEGER NOT NULL, repertoire TEXT NOT NULL, parent_fen TEXT NOT NULL, move_uci TEXT NOT NULL, PRIMARY KEY (study_id, repertoire, parent_fen, move_uci), FOREIGN KEY(study_id) REFERENCES repertoire_studies(id) ON DELETE CASCADE)
```

**(b) `blunders` — 7 undeclared columns.** The doc says:

> `AGENTS.md:161-165` — "`id` (INTEGER, PK AUTOINCREMENT), `game_id` (FK `games.id`).
> `move_number`, `ply`, `color`. `fen_before`, `fen_after`, `played_move` (UCI),
> `played_san`, `best_move` (UCI), `best_san`. `eval_before`, `eval_after`, `cpl_loss`.
> `opening_name`, `eco`, `refutation_pv`, `opening_games` (count in 2000+ DB)."

The code has, undeclared: `is_book_move INTEGER DEFAULT 0` (`db.py:75`),
`explanation TEXT` (76), `strategic_idea TEXT` (77), `category TEXT` (78),
`created_at INTEGER` (81) — plus `best_pv` in the live DB only (CODE-02-01). The doc also
never mentions `best_pv`, which *is* written and read (`analyzer.py:231`,
`api.py:565-571`, `api.py:766-773`).

**(c) `scouted_content.source_type` enum drift.** The doc says:

> `AGENTS.md:191` — "`source_type` (TEXT): `'youtube'`, `'eco_guide'`, `'lichess_study'`, or `'pgn'`."

The code comment says:

```python
# backend/db.py:196
source_type TEXT DEFAULT 'youtube', -- 'youtube', 'lichess_study', 'pgn'
```

`'eco_guide'` is missing from the comment yet *is* written by `scout.py:151, 602, 631`
(and asserted by `tests/test_scout.py:48`) — so the **code comment** is the stale one.

**(d) `parent_fen` normalisation drift.** The doc says:

> `AGENTS.md:172` — "`parent_fen` (TEXT): Normalized FEN (pieces, turn, castling rights)."

`normalize_fen` returns **four** tokens (it includes the en-passant square):
`repertoire.py:24` — *"Normalize FEN to pieces, turn, castling rights, and en passant
square (first 4 tokens)"*. The 3-token form the doc describes is what `db.py:324-344` and
~10 sites in `repertoire.py` actually key on.

**(e) `PRAGMA foreign_keys` is never enabled.** `get_db()` sets only:

```python
# backend/db.py:17-22
def get_db():
    current_path = os.environ.get("CHESS_DB_PATH") or DB_PATH
    conn = sqlite3.connect(current_path, timeout=30.0)
    conn.row_factory = sqlite3.Row
    conn.execute("PRAGMA journal_mode=WAL")
    return conn
```

SQLite defaults `foreign_keys` to **OFF**, so all three declared foreign keys
(`blunders.game_id` → `games(id)`, `drill_reviews.blunder_id` → `blunders(id)`,
`study_moves.study_id` → `repertoire_studies(id) ON DELETE CASCADE`) are **unenforced**,
and the `ON DELETE CASCADE` at `db.py:177` is dead DDL. `repertoire.delete_study`
(`repertoire.py:794-795`) happens to delete `study_moves` manually, so the bug is
currently masked — but the schema advertises a guarantee it does not provide.
`grep -rn "foreign_keys" --include=*.py .` → zero hits.

## Root cause
The schema grew by accretion (`ALTER TABLE` migrations at `db.py:86-90` and
`db.py:138-154`, both of which are no-ops because the columns are already in the
`CREATE TABLE`) and the doc was never regenerated. SQLite's non-default FK enforcement was
simply never switched on, so the declared relationships have never been tested.

## Exploit / escalation
1. `INSERT INTO blunders (game_id, ...)` with a `game_id` that does not exist in `games`
   succeeds. `GET /api/blunders`'s inner `JOIN games g` then silently drops the row
   (`api.py:502`), so a corrupted blunder is invisible rather than reported.
2. Turning `PRAGMA foreign_keys=ON` as a "fix" would immediately change
   `INSERT OR REPLACE INTO games` (`api.py:245`, `repertoire.py:1465, 1567, 1824`) from an
   upsert into a `DELETE`+`INSERT` that cascades away the game's blunders — a latent
   data-loss trap (see CODE-02-11).
3. A fixer reading only `AGENTS.md` §5 will not know `drill_reviews`, `settings`,
   `repertoire_studies` or `study_moves` exist, and will add a *second* `settings` table.
