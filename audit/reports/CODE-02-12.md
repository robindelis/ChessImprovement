# CODE-02-12 — Six live routes are three duplicated pairs: `/api/scout/*` and `/api/repertoire/*` expose byte-identical handlers
- **Severity:** medium
- **Type:** spec-violation
- **File:** `backend/api.py`
- **Line(s):** 1058-1116
- **Component:** REST API surface
- **Repro script:** `audit/scripts/CODE-2_routes.py` (route inventory)
- **Detected by:** CODE-2

## Expected
One canonical path per operation; an alias at most, and then documented and thin.

## Actual
`api.py` ends with three pairs where the second handler is a **verbatim copy** of the
first, including the identical `try/except Exception -> HTTPException(400, str(e))` body:

```python
# backend/api.py:1058-1065  (canonical, used by frontend/scout.js:1652, 1732)
@app.post("/api/scout/import_repertoire")
def scout_import_repertoire(payload: ScoutImportPayload):
    """Imports an extracted line or variation into the user's Repertoire tree."""
    scout = ContentScout.get_instance()
    try:
        return scout.import_line_to_repertoire(repertoire=payload.repertoire, moves=payload.moves, study_name=payload.study_name)
    except Exception as e:
        raise HTTPException(status_code=400, detail=str(e))

# backend/api.py:1091-1098  (duplicate, used by frontend/repertoire_builder.js:3024, 3084)
@app.post("/api/repertoire/import_line")
def repertoire_import_line(payload: ScoutImportPayload):
    """Imports a sequence of moves as a whole line into the user's Repertoire tree."""
    scout = ContentScout.get_instance()
    try:
        return scout.import_line_to_repertoire(repertoire=payload.repertoire, moves=payload.moves, study_name=payload.study_name)
    except Exception as e:
        raise HTTPException(status_code=400, detail=str(e))
```

| Operation | Canonical | Duplicate | Bodies identical? |
|---|---|---|---|
| import line | `POST /api/scout/import_repertoire` (1058) | `POST /api/repertoire/import_line` (1091) | yes |
| check one line | `POST /api/scout/check_line` (1067) | `POST /api/repertoire/check_line` (1100) | yes |
| check tree | `POST /api/scout/check_tree` (1076) | `POST /api/repertoire/check_tree` (1109) | yes |

**Both sides of every pair are live**: `frontend/scout.js` calls the `/api/scout/*` form
(`scout.js:1422, 1491, 1652, 1732`) and `frontend/repertoire_builder.js` calls the
`/api/repertoire/*` form (`repertoire_builder.js:2617, 2672, 3024, 3084`).

There is a fourth, related duplication: the whole `ContentScout` + `try/except ->
HTTPException(400, str(e))` preamble is repeated verbatim seven times
(`api.py:1044, 1058, 1067, 1076, 1091, 1100, 1109`) with no shared dependency or helper.

The same duplication exists on the sync axis: `POST /api/games/sync_recent` (404),
`GET /api/games/sync_recent_stream` (409), `POST /api/repertoire/sync_games` (1013),
`GET /api/repertoire/sync_games_stream` (1019) and the fully-orphaned `POST /api/sync`
(198) — five entry points into the same "fetch user games" operation, with five different
`max_games` defaults (15 / 20 / 30 / `None` / 30) and two different `max_ply` values.

## Root cause
No route registry and no single-owner convention. Frontend files were written
independently against "the API" and each invented its own path, and the backend grew an
alias per caller instead of a redirect.

## Exploit / escalation
1. Divergence trap: patching `scout_import_repertoire` (e.g. adding auth or a size limit)
   leaves `repertoire_import_line` unprotected — and a caller can trivially pick the
   unchecked one.
2. `AGENTS.md` §3/§4 document neither alias, so a fixer reading the doc will not know both
   exist.
3. Adjacent: the identical `except Exception as e: raise HTTPException(400, str(e))` in
   all seven scout routes is the same raw-exception-string leak reported in CODE-02-13.
