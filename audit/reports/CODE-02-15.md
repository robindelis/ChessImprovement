# CODE-02-15 — `normalize_fen` is copy-pasted verbatim into two modules with a third weaker variant; SAN-token filtering is duplicated three more times
- **Severity:** medium
- **Type:** spec-violation
- **File:** `backend/evaluator.py`, `backend/openings.py` (duplicates of `backend/repertoire.py`)
- **Line(s):** evaluator.py:17-28; openings.py:25-30; api.py:363; openings.py:87; analyzer.py:122
- **Component:** FEN normalisation / SAN parsing
- **Repro script:** n/a (static diff)
- **Detected by:** CODE-2

## Expected
One canonical `normalize_fen` and one canonical "strip move numbers / annotations" helper,
imported everywhere.

## Actual
`backend/evaluator.py:17-28` is **byte-for-byte identical** to `backend/repertoire.py:23-34`
(including the docstring):

```python
# backend/evaluator.py:17-28
def normalize_fen(fen: str) -> str:
    """Normalize FEN to pieces, turn, castling rights, and en passant square (first 4 tokens)."""
    if not fen or not isinstance(fen, str):
        return ""
    parts = fen.strip().split()
    if len(parts) >= 4:
        return " ".join(parts[:4])
    try:
        b = chess.Board(fen.strip())
        return " ".join(b.fen().split()[:4])
    except Exception:
        return fen.strip()
```

A third, *weaker* variant exists as a method:

```python
# backend/openings.py:25-30
def _normalize_fen(self, fen: str) -> str:
    # Keep piece placement, active color, castling rights, and en passant (first 4 components)
    parts = fen.split()
    if len(parts) >= 4:
        return " ".join(parts[:4])
    return fen.strip()
```

Differences that matter:
- no `isinstance` guard → `None.split()` raises `AttributeError` (the other two return `""`);
- no `chess.Board` re-serialisation for a short FEN → a 3-token FEN is returned
  **un-normalised** and can therefore never match a 4-token key;
- `fen.split()` without `.strip()`, unlike the other two.

Because `openings.py` is the module that builds `fen_to_opening`, this variant defines the
lookup keys for the whole ECO book.

The same "strip `N.` prefixes and `?!#+` annotations" logic is written out four times:

```python
# backend/openings.py:87
san_moves = [t for t in tokens if not t.endswith(".") and not t[0].isdigit()]
```

```python
# backend/analyzer.py:122
clean_san = re.sub(r"[?!#+]", "", san).strip()
```

```python
# backend/api.py:363
tokens = [m for m in moves_san.strip().split() if m and not m.endswith(".") and not m[0].isdigit()]
```

and implicitly a fourth time at `openings.py:150`. Note that `api.py:363` filters
move numbers but **not** `?!#+`, so a `moves_san` containing annotations yields different
token counts in `api.py` than in `analyzer.py`.

## Root cause
No shared utility module. `backend/db.py` even reaches into `backend.repertoire` and
`backend.openings` *inside a migration function* (`db.py:265-267`) to get `normalize_fen`,
so a circular-import constraint was solved by copy rather than by import.

## Exploit / escalation
1. Change `normalize_fen` (e.g. to also normalise castling-rights ordering) in
   `repertoire.py` only → `evaluator.py`'s eval cache and `openings.py`'s book keys silently
   diverge, and `/api/repertoire/eval_stream` reports stale cached evals for transposed
   positions.
2. `openings._normalize_fen` raising on `None` is reachable: a single NULL `fen` reaching
   `get_opening_for_fen` would 500 rather than return `None`, whereas the other two
   variants return `""`/`None` gracefully.
3. Adjacent: `AGENTS.md` §5.3 documents `parent_fen` as *"Normalized FEN (pieces, turn,
   castling rights)"* — **three** tokens — while `normalize_fen` produces **four** (it
   includes en passant). The doc therefore contradicts the code *and* the
   3-token-only reachability logic in `db.py:324-344` and `repertoire.py`.
