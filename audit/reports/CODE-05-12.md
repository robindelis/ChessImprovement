# CODE-05-12 — 401 MB of the repository is tracked build/vendor output: `node_modules/`, `__pycache__/*.pyc`, a 103 MB Stockfish binary and the full upstream Stockfish source tree
- **Severity:** medium
- **Type:** spec-violation
- **File:** `.gitignore`
- **Line(s):** 1-5 (and the file is untracked)
- **Component:** Repo hygiene
- **Repro script:** `git ls-files` (see "Actual")
- **Detected by:** CODE-5

## Expected
A `.gitignore` that is committed, listing `node_modules/`, `__pycache__/`, `*.pyc`, `*.db`, `*.db-wal`, `*.db-shm`, `.env`.

## Actual
`.gitignore` exists but **is not tracked** (`?? .gitignore` in `git status --porcelain`), and adding it would not help because the paths are *already* tracked — `gitignore` only affects untracked files:

```
$ git ls-files node_modules | wc -l
555
$ git ls-files | grep -c __pycache__
15
$ git ls-files | grep stockfish-linux-x86-64-universal
bin/stockfish/stockfish-linux-x86-64-universal
$ git status --porcelain | grep -c pycache
15                       # all 15 .pyc files are listed as MODIFIED
```

Sizes:

```
$ du -sh .git
203M	.git
$ git ls-files -z | xargs -0 du -ch | tail -1
401M	total
$ ls -la bin/stockfish/stockfish-linux-x86-64-universal
-rwxr-xr-x 1 robin robin 103153472 ... stockfish-linux-x86-64-universal
$ git ls-files node_modules | grep -c "dist/"
99                        # Chromium/Electron binaries
```

The `.pyc` files are actively dirty, so they churn in every diff:
```
 M backend/__pycache__/api.cpython-314.pyc
 M backend/__pycache__/db.cpython-314.pyc
 M backend/__pycache__/repertoire.cpython-314.pyc
 M backend/__pycache__/scout.cpython-314.pyc
 M tests/__pycache__/test_api.cpython-314.pyc
 ... (15 total)
```

Also committed: the complete upstream Stockfish C++ source tree (100 files under `bin/stockfish/src/`, `wiki/`, `scripts/`, licence and `AUTHORS` files) even though only the compiled binary is used. `AGENTS.md:81` describes the directory as:
> `bin/stockfish/  # Local Stockfish 19 UCI binary (universal Linux x86_64)`

which does not mention ~100 vendored source files.

The binary is **x86-64-only** and unversioned-by-hash; `electron/main.js` and `backend/*.py` hardcode the filename `stockfish-linux-x86-64-universal` in five places (`backend/repertoire.py:18-21`, `backend/analyzer.py:11-14`, `backend/evaluator.py:12-15`, `start.py:23-26`, plus `AGENTS.md:14` and `AGENTS.md:227`), so an ARM or non-Linux checkout silently loses engine support.

## Root cause
The repository was initialised (`81f4ed6 Initial commit`) with the working directory contents already in place, and `.gitignore` was written afterwards and never staged. There is no `pre-commit` hook and no CI configuration in the repo to catch it.

## Exploit / escalation
1. Every clone pulls 401 MB, of which 203 MB is `.git` history, to obtain ~350 KB of actual source (`backend/*.py` + `frontend/*.js`).
2. The dirty `.pyc` files guarantee a non-empty `git diff` on every single test run — 15 spurious modified files that hide real changes in review.
3. Adjacent variants with the same root cause (untracked-by-policy state that should be policy):
   - `package-lock.json` **is** tracked (correct) but `node_modules/` is too, so `npm ci` and the committed tree can silently disagree; there is no `engines` field in `package.json` and no `npm`/`node` version pin, while `run-desktop.sh:8` hardcodes `/home/robin/.local/bin:/home/robin/miniconda3/bin` onto `PATH`.
   - `chess_improvement.db` is tracked (CODE-05-02) and `.gitignore` does not list `*.db`, `*.db-wal` or `*.db-shm` — so even after `git rm --cached`, one `start.py` run recreates the WAL sidecars as untracked-but-not-ignored noise.
   - `audit/` is untracked but `audit/reports/*.tmp` is the only audit path in `.gitignore`; `audit/scripts/*.py` (my own repros included) are neither committed nor ignored, so a future `git add -A` sweeps them in.
