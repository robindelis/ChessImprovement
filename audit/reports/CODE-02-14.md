# CODE-02-14 — `openings.py` builds a full second copy of the opening database (`move_tree`) that nothing ever reads, and `get_strategic_ideas` ignores its `eco` argument
- **Severity:** medium
- **Type:** spec-violation
- **File:** `backend/openings.py`
- **Line(s):** 14, 81-127 (`move_tree` build), 226-238 (`get_strategic_ideas`), 142-178 (`identify_game_opening`)
- **Component:** ECO encyclopedia
- **Repro script:** `audit/scripts/CODE-2_repro.py` (PROBE 4)
- **Detected by:** CODE-2

## Expected
Data structures are built because something reads them; function parameters are used
because the caller supplies them.

## Actual
**(a) `move_tree` is dead.** It is declared and populated, and never read:

```python
# backend/openings.py:14
self.move_tree = {}      # trie of UCI moves: node = {'children': {}, 'eco': ..., 'name': ...}
```

```python
# backend/openings.py:123-127 (inside _index_pgn_entry, per ply of every opening)
if "children" not in current_node:
    current_node["children"] = {}
if uci not in current_node["children"]:
    current_node["children"][uci] = {"children": {}, "eco": eco, "name": name}
current_node = current_node["children"][uci]
```

`grep -rn "move_tree" backend/` returns exactly two hits — the declaration (line 14) and
the initial alias (line 83). No lookup ever touches it. It duplicates the entire
`openings_data/*.tsv` corpus (3 820 lines across `a.tsv`…`e.tsv`) in a *third* structure
next to `fen_to_opening`, purely as a load-time cost.

**(b) `get_strategic_ideas` ignores `eco`.**

```python
# backend/openings.py:226-238
def get_strategic_ideas(self, eco: str, opening_name: str) -> dict:
    safe_name = str(opening_name or "")
    for key, theme in self.opening_themes.items():
        if key.lower() in safe_name.lower():
            return theme

    # Generic strategic guidance if opening not in top families
    return {
        "name": safe_name or "Opening Phase",
        "core_idea": f"In the {safe_name or 'opening'}, ...",
        ...
    }
```

`eco` is never referenced in the body. The single caller passes it:

```python
# backend/api.py:579
ideas = OpeningBook.get_instance().get_strategic_ideas(data.get("eco", ""), data.get("opening_name", ""))
```

Observed:

```
eco='B70' name=''  -> Opening Phase
eco='B20' name=''  -> Opening Phase
eco=''    name='Sicilian Defense' -> Sicilian Defense
```

A position with a perfectly good ECO but a blank/`Unknown` opening name always falls back
to the generic "Opening Phase" text, even for `B70` (Sicilian) or `B12` (Caro-Kann).

**(c) `identify_game_opening` hands out a reference to the book's internal dict.**

```python
# backend/openings.py:174-178
if norm in self.fen_to_opening:
    deepest = self.fen_to_opening[norm]
return deepest
```

`deepest` is not a copy — it aliases `self.fen_to_opening[norm]`, which is also what
`_index_pgn_entry` writes to. Any caller that mutates the returned dict (e.g. adding a
`ui_label`) would corrupt the shared singleton for the whole process. Current callers only
read, so this is latent.

## Root cause
Structures and parameters accreted during earlier iterations with no removal pass. The
`eco` argument is a leftover from an ECO-keyed theme lookup that was replaced by a
name-substring scan but never deleted from the signature or the call site.

## Exploit / escalation
1. Startup cost: `_load_openings` builds a redundant trie for ~3 800 PGNs on every process
   start (and `OpeningBook.get_instance()` is invoked from `init_db`'s migration at
   `db.py:268`, `api.py:320`, `analyzer.py:19`, `repertoire.py`).
2. `get_strategic_ideas` is a substring scan over `opening_themes` keys in dict order — the
   first match wins, so `"Queen's Gambit"` is checked before `"Caro-Kann"`, and an opening
   named e.g. `"Sicilian Defense: Caro-Kann Accelerated"` matches `Sicilian` first purely
   by insertion order (`openings.py:181-224`).
3. Adjacent: `search_openings` (`openings.py:54-67`) and `find_opening_by_name`
   (`openings.py:69-79`) are each up to two full linear scans of the 3 800-entry
   `openings_list`, and `search_openings` is called from `scout.py` 6 times — on a
   user-typed search query (`scout.js:402` → `GET /api/scout/search`) and once per video
   chapter title (`scout.py:233`).
