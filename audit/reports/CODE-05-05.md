# CODE-05-05 — The four "spam resistance" tests in `test_timeline_spam.py` run against a hand-written JS mock, not the application
- **Severity:** high
- **Type:** spec-violation
- **File:** `tests/test_timeline_spam.py`
- **Line(s):** 52-183 (mock at 58-170), tests at 185, 240, 275, 333
- **Component:** Test suite
- **Repro script:** `audit/scripts/CODE-05_repro_timeline_false_positive.py`
- **Detected by:** CODE-5

## Expected
A test named `test_rapid_right_arrow_spamming` / `test_chaotic_alternating_arrow_spamming` verifies the real `RepertoireBuilder.stepForward` / `jumpToStep` / `onBoardMove` and the real `InteractiveChessboard.stopAnimations` in `frontend/repertoire_builder.js` and `frontend/board.js`. If those modules regress, the tests fail.

## Actual
`tests/test_timeline_spam.py:83-170` embeds a **complete re-implementation** of the timeline logic in JavaScript inside the Python file and executes *that*:

```python
    def _run_node_simulation(self, js_test_code: str) -> dict:
        wrapped_script = f"""
        const {{ Chess }} = require('{os.path.join(FRONTEND_DIR, "vendor", "chess.min.js")}');

        // Mock minimal browser environment for simulation
        class MockBoard {{
            constructor() {{ this.chess = new Chess(); this.activeAnimations = []; }}
            ...
        }}

        class MockRepertoireBuilder {{
            constructor() {{ ... this.initHistory(); }}
            initHistory() {{ ... }}
            stepBackward() {{ ... }}
            stepForward() {{ ... }}
            jumpToStep(idx) {{ ... }}
            onBoardMove(playedUci, playedSan) {{ ... }}
        }}

        {{js_test_code}}
        """
```

`FRONTEND_DIR` is used **only** to locate the vendored `chess.min.js` (line 55). Neither `board.js` nor `repertoire_builder.js` is ever loaded, parsed, or executed. Proof — replacing both production modules with empty files and re-running:

**4 of the 5 tests pass with the entire timeline implementation deleted.** Only `test_static_code_invariants_board_and_builder` (line 24) fails, and that test is not a behavioural test at all — it is `assertIn` on raw source text:

```python
self.assertNotIn("this.chess.undo()", board_js, ...)
self.assertIn("stopAnimations", board_js, ...)
self.assertIn("nextStepInHist.uci === playedUci", builder_js, ...)
self.assertIn("this.currentEvalAbort.abort()", builder_js, ...)
```

A code comment, a dead branch, or a string literal anywhere in the file satisfies these. They are grep-as-a-test.

## Root cause
The mock was written to reproduce the expected behaviour instead of importing the subject under test. Nothing in the suite asserts that the mock and the production code agree, so the two can (and do) diverge freely; the mock is now the de-facto specification and is unverified.

## Exploit / escalation
1. Delete `frontend/repertoire_builder.js` and `frontend/board.js` entirely — 4 of the 5 tests in this file still pass. These are the tests that were presumably added to prove a timeline-duplication/desync fix; they cannot detect its regression.
2. Introduce a real desync in `RepertoireBuilder.jumpToStep` (e.g. remove the `stopAnimations()` call) — the spam tests stay green because they never call it.
3. Adjacent variants with the same root cause (tests that assert on text rather than behaviour):
   - `test_static_code_invariants_board_and_builder` itself — renaming `currentEvalAbort` to anything else fails a "test" that never checks that the abort happens.
   - `tests/test_user_workflows.py:251,271,273,277,279` asserts directly against SQL counts (`c.fetchone()[0] == 0`), i.e. it pins internal table state rather than the API contract, so a schema rename breaks it while a behaviour regression does not.
   - `tests/test_timeline_spam.py` shells out to `node -e` (line 175-176) with no `shutil.which("node")` guard, so the whole file errors out with `FileNotFoundError` on any machine without Node on `PATH`, even though Node is not a declared test dependency.
