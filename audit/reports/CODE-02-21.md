# CODE-02-21 — `start.py`: generic `PORT` env var silently overrides the documented default, an empty `CHESS_PORT` crashes the launcher, and port-in-use is unhandled
- **Severity:** low
- **Type:** spec-violation
- **File:** `start.py`
- **Line(s):** 8, 11, 19, 51, 56
- **Component:** Launcher
- **Repro script:** n/a (static read)
- **Detected by:** CODE-2

## Expected
`AGENTS.md` §7: *"Default Port: `38281` (configurable via `CHESS_PORT` or `--port`)."*
An empty/invalid value should produce a clear error, and a busy port should produce an
actionable message.

## Actual
```python
# start.py:51
parser.add_argument("--port", "-p", type=int,
                    default=int(os.environ.get("CHESS_PORT", os.environ.get("PORT", DEFAULT_PORT))),
                    help=f"Port to bind to (default: {DEFAULT_PORT})")
```

1. **Undocumented `PORT` fallback.** The precedence is
   `CHESS_PORT` → `PORT` → `38281`. `PORT` is a near-universal environment variable (Heroku,
   Cloud Run, most PaaS images, many dev containers set it). Any such environment silently
   moves the app off the documented port, and — because `electron/main.js` and every
   `frontend/*.js` `fetch()` are hard-relative — the desktop shell will then probe the
   wrong URL. `AGENTS.md` §2 warns *"DO NOT USE PORT 8000"*; nothing prevents exactly that.
2. **`int("")` raises an unhandled `ValueError`.** `CHESS_PORT=""` (which is what an
   unset-but-declared variable looks like in many shells/CI configs) produces
   `ValueError: invalid literal for int() with base 10: ''` as a bare traceback before
   `argparse` ever runs — `default=` is evaluated at parser-construction time, so there is
   no friendly error path.
3. **No port-in-use handling.** `setup(port=args.port)` prints
   `"Starting Web Application on http://127.0.0.1:{port}"` (line 45) *before*
   `uvicorn.run(...)` (line 56) binds. If the port is busy, uvicorn raises
   `OSError: [Errno 98] Address already in use` and the user sees a raw traceback after a
   reassuring banner. The Electron shell has a 25 s poll loop
   (`electron/main.js:76-79`) and will attach to the *other* process on that port, which may
   be an older build of the same app.
4. **Unused imports.** `import sys` (line 6) and `get_setting`, `set_setting` (line 8) are
   never used.
5. `uvicorn.run("backend.api:app", ...)` uses a **string** import, so `backend.api` is
   imported by uvicorn's reloader machinery in a second import context. Harmless here
   (no `--reload`), but it means `init_db()` at `start.py:19` and the module-level
   `app.mount(...)` at `api.py:1120` execute in a module that is imported twice if
   uvicorn's import string is resolved twice.

## Root cause
`--port` precedence was bolted onto an argparse default expression rather than resolved
explicitly with validation, and the pre-flight output is printed before the bind succeeds.

## Exploit / escalation
1. `PORT=8000 /home/robin/miniconda3/bin/python3 start.py` → the app binds 8000, in direct
   violation of `AGENTS.md` §2, and the other project on 8000 is clobbered or the launch
   fails with no hint.
2. `CHESS_PORT= python3 start.py` → bare `ValueError` traceback instead of
   `error: argument -p/--port: invalid int value`.
3. Adjacent: `setup()` also performs a **live Lichess API call** at import time
   (`start.py:33-41`, `client.get_account_profile()` with a 10 s timeout) before the server
   binds, so a slow or unreachable lichess.org adds up to 10 s to every launch.
