# CODE-02-02 — The catch-all `StaticFiles("/")` mount swallows every `405 Method Not Allowed` under `/api/`
- **Severity:** high
- **Type:** wrong-result / spec-violation
- **File:** `backend/api.py`
- **Line(s):** 1118-1121
- **Component:** FastAPI router / static mount
- **Repro script:** `audit/scripts/CODE-2_routes.py`
- **Detected by:** CODE-2

## Expected
`GET /api/sync` (a path that exists but only accepts `POST`) must return
`405 Method Not Allowed`. That is what Starlette's router does via its `Match.PARTIAL`
path when nothing later in the route table matches `FULL`.

## Actual
`api.py` ends with a mount of `StaticFiles` at the **root**:

```python
# backend/api.py:1118-1121
# Mount static frontend files
FRONTEND_DIR = os.path.join(os.path.dirname(os.path.dirname(os.path.abspath(__file__))), "frontend")
if os.path.exists(FRONTEND_DIR):
    app.mount("/", StaticFiles(directory=FRONTEND_DIR, html=True), name="frontend")
```

`Mount("/")` matches **every** path with `Match.FULL`. Starlette's `Router.__call__`
records a `PARTIAL` match but keeps iterating, and the root mount then returns `FULL`, so
the 405 branch is never reached and `StaticFiles` produces the 404.

Observed (`audit/scripts/CODE-2_routes.py`, section 1):

```
  GET  /api/sync                    -> 404 {"detail":"Not Found"}
  GET  /api/repertoire/clear        -> 404 {"detail":"Not Found"}
  GET  /api/repertoire/move         -> 404 {"detail":"Not Found"}
  POST /api/blunders                -> 405 {"detail":"Method Not Allowed"}
```

Note the inconsistency *within the same table*: `/api/blunders` has a `GET` route
registered, so the router's partial branch fires before the mount is reached and correctly
returns 405. Every API path that has **no** `GET` route returns 404 instead.

## Root cause
The root mount is a catch-all that converts Starlette's `PARTIAL` (405) semantics into
`StaticFiles`' 404 for the entire `/api/` namespace. Since the frontend is a zero-build
vanilla app served from the same origin, a client typo or a wrong-verb call gets a
"not found" that is indistinguishable from a genuinely removed endpoint.

## Exploit / escalation
1. Any removed/renamed endpoint that is still partially matched (e.g. `POST`-only paths)
   produces a 404 whose body is `{"detail":"Not Found"}` — identical to a real
   "endpoint never existed". Debugging a frontend/backend version skew becomes guesswork.
2. `DELETE /api/repertoire/move` requires a JSON **body** (`DeleteMovePayload`); a client
   that sends it as a query string gets 404, not 400/422, so the failure mode is opaque.
3. Adjacent: because the mount also owns `/`, a `GET` on a nonexistent `/api/<typo>`
   returns `{"detail":"Not Found"}` with `content-type: application/json`, while a
   `GET /api/` (directory) is served by `StaticFiles(html=True)` — two different
   content contracts behind one path prefix.
