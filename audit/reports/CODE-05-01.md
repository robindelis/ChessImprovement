# CODE-05-01 — Live Lichess API token committed to git in `.env`
- **Severity:** critical
- **Type:** security
- **File:** `.env`
- **Line(s):** 1
- **Component:** Repo hygiene / secrets
- **Repro script:** `audit/scripts/CODE-05_repro.py` (see "Actual" for the exact commands)
- **Detected by:** CODE-5

## Expected
`.env` holding a credential is git-ignored and untracked. `git grep lip_` over history returns nothing. The token is sourced from the `settings` table (already the first-priority source in `backend/lichess_client.py:21`).

## Actual
`git ls-files` lists `.env` as a tracked file, and it contains a bare Lichess API token:

```
$ git ls-files | head -1
.env
$ git show HEAD:.env
lip_***REDACTED***
```

The token is present in the only commit in the repository:

```
$ git log --oneline --all -- .env
81f4ed6 Initial commit
```

`.gitignore` exists but **is itself untracked** (`git status --porcelain` → `?? .gitignore`) and does not list `.env` anyway:

```
$ cat .gitignore
node_modules/
__pycache__/
*.pyc
.pytest_cache/
audit/reports/*.tmp
```

`backend/lichess_client.py:19-38` reads this exact file at runtime as fallback source #2, so the committed value is a live credential, not a placeholder.

## Root cause
`backend/lichess_client.py:25-38`:
```python
# 2. Check .env file in project root
env_path = os.path.join(os.path.dirname(os.path.dirname(os.path.abspath(__file__))), ".env")
if os.path.exists(env_path):
    with open(env_path, "r", encoding="utf-8") as f:
        content = f.read().strip()
        if "lip_" in content:
```
A file deliberately designed to hold a bearer token is stored inside the repository working tree, was added in the initial commit, and is not covered by `.gitignore`. Every clone of this repo receives a working credential for `RobiDeli`'s Lichess account.

## Exploit / escalation
1. `git clone <repo>` → `cat .env` → full read/write Lichess API access as the victim for as long as the token is valid (Lichess `lip_` tokens do not expire on a schedule).
2. Adjacent variants with the same root cause (credential material inside the tracked tree):
   - `chess_improvement.db` holds `settings.lichess_username = RobiDeli` plus 307 real game move lists (see CODE-05-02) — enough to reconstruct the account's entire public activity and to correlate it with the token.
   - `git log -p` will hand the token to anyone who later force-pushes/amends, so removing the file now is insufficient; the blob stays reachable in `81f4ed6` until history is rewritten and the token is **revoked**.
   - `.gitignore` being untracked means the next `git add -A` adds nothing new for `node_modules/`/`__pycache__` either, but also that a future `.env.local` or `*.pem` would be silently committed.
