## Root cause
No linting (`ruff`/`flake8`) is configured in the repo or in CI, and migrations were never
pruned after the `CREATE TABLE` statements absorbed them.

## Exploit / escalation
1. The `except Exception: pass` around each no-op `ALTER` (item 6) is a live hazard: on a
   locked or read-only database, `init_db()` still returns successfully and the app starts
   against an unmigrated schema. This is the same swallowing pattern as CODE-18.
2. Item 10's unindexed scan backs the Scout search box: typing a query with no match walks
   all ≈3 800 openings per keystroke on the request thread.
3. Adjacent (not dead, but drift-prone): `Query(None, regex="^(white|black)$")` at
   `api.py:284` emits a `FastAPIDeprecationWarning: 'regex' has been deprecated, please use
   'pattern' instead` on every startup, and is the only place in the file that does manual
   validation instead of the `Literal["white","black"]` used by every sibling route
   (`api.py:800, 810, 896, 939, 989`) — a second way of expressing the same enum.
