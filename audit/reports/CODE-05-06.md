## Expected
`test_evaluator_illegal_fen_safety` builds a corrupt FEN (`"P7/8/8/8/8/8/8/k6K w - - 0 1"` — an illegal pawn on the 8th rank), feeds it to `AsyncEngineEvaluator.stream_eval`, awaits the coroutine, and asserts that the evaluator refuses it rather than crashing the engine process.

## Actual
The test body defines an `async def run_eval()` and **never calls it**. There is no `assert` of any kind, no `asyncio.run(...)`, no `self.assert*`:


## Root cause
`run_eval` was declared and its body written, but the two lines that would actually exercise and verify it (`events = asyncio.run(run_eval())` and an assertion) were never added. The test passes unconditionally and would continue to pass if `AsyncEngineEvaluator` were deleted from the codebase.

## Exploit / escalation
1. Replace `backend/evaluator.py`'s `stream_eval` with `async def stream_eval(self, *a, **k): raise RuntimeError("boom")` — this test still passes. The engine-safety coverage it advertises is zero.
2. A real crash in `stream_eval` on a malformed FEN (which would kill the shared singleton engine and break every subsequent eval in the app) is not detected here — it is only caught at the HTTP layer by `test_api.py:158-165` (`test_eval_stream_fen_validation`), which uses a *different* FEN (`"8/8/8/8/8/8/8/8 w - - 0 1"`) and never exercises the pawn-on-rank-8 case the test name advertises.
3. Adjacent variants with the same root cause (empty/tautological tests elsewhere in the suite):
