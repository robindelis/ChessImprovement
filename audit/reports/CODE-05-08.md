# CODE-05-08 — `AGENTS.md` §5 "Database Schema" is wrong for 4 of 9 tables and omits 12+ columns
- **Severity:** medium
- **Type:** spec-violation
- **File:** `AGENTS.md`
- **Line(s):** 148-194
- **Component:** Documentation
- **Repro script:** `audit/scripts/CODE-05_schema_dump.py`
- **Detected by:** CODE-5

## Expected
§5 "Database Schema (`chess_improvement.db`)" enumerates every table and column exactly as `backend/db.py` creates them, including types, `NOT NULL`, `DEFAULT`, and unique/foreign-key constraints — because every other agent is told to treat this document as authoritative.

## Actual
The real schema, extracted from `backend/db.py` by `audit/scripts/CODE-05_schema_dump.py`, is **9 tables**. `AGENTS.md` §5 documents **5**.

### Entirely undocumented tables
| Table | Purpose | Referenced by |
| :--- | :--- | :--- |
| `settings (key TEXT PRIMARY KEY, value TEXT)` | stores `lichess_username`, `lichess_token`, `max_opening_ply`, `blunder_threshold_cp`, `gap_threshold`, `recent_learned_opening` | `POST/GET /api/settings`, `backend/lichess_client.py:21`, `start.py` |
| `drill_reviews` — 10 columns (`blunder_id INTEGER UNIQUE`, `attempts`, `successes`, `last_attempt_date`, `next_review_date`, `interval_days REAL DEFAULT 1.0`, `ease_factor REAL DEFAULT 2.5`, `status TEXT DEFAULT 'new'`) | the entire spaced-repetition subsystem | `GET /api/train/paths`, `mastered_count` / `due_reviews_count` in `/api/dashboard`, `GET /api/blunders/{id}` |
| `repertoire_studies` (`name TEXT NOT NULL`, `repertoire TEXT NOT NULL`, `description`, `created_at`, `updated_at`, `UNIQUE(name, repertoire)`) | the named-studies feature | `GET/POST /api/repertoire/studies`, `DELETE /api/repertoire/studies/{id}`, `?study=` on `/api/repertoire/train/progress`, `study_name` on every repertoire move |
| `study_moves` (`study_id/repertoire/parent_fen/move_uci` all `NOT NULL`, `PRIMARY KEY (study_id, repertoire, parent_fen, move_uci)`, `FOREIGN KEY(study_id) REFERENCES repertoire_studies(id) ON DELETE CASCADE`) | many-to-many study↔move association | ditto |

The whole **studies subsystem** — 3 API routes, 3 frontend consumers (`frontend/scout.js`, `frontend/repertoire_builder.js`, `frontend/repertoire_trainer.js`), a dedicated 7-test file `tests/test_studies.py`, and the `drill_reviews` spaced-repetition engine — is absent from the document.

### Undocumented columns in documented tables
- `games`: `opening_name TEXT`, `eco TEXT` are missing (real definition `backend/db.py:49-50`).
- `blunders`: `is_book_move INTEGER DEFAULT 0`, `explanation TEXT`, `strategic_idea TEXT`, `category TEXT`, `created_at INTEGER` are missing (`backend/db.py:75-81`). Both `explanation` and `strategic_idea` are surfaced by `GET /api/blunders/{blunder_id}` (`backend/api.py:787-788`) and by `/api/dashboard`'s `recent_blunders`.
- `repertoire_moves`: `study_name TEXT DEFAULT ''` and `created_at INTEGER` are missing (`backend/db.py:127, 133`).

### The constraint that is claimed but absent
`AGENTS.md:174`:
> `is_user_move` (INTEGER): `1` for user move (**enforces 1 move per position**), `0` for opponent response branch.

The real table has `UNIQUE(repertoire, parent_fen, move_uci)` (`backend/db.py:134`) — which permits **many** moves per position. The "one move per position" rule is enforced only procedurally, in `backend/repertoire.py:477-489`, and that code path also `DELETE`s the previous user move and recursively prunes its subtree — behaviour §5 says nothing about.

### Minor
- `AGENTS.md:180` lists `interval_days` last with no type; the real type is `REAL DEFAULT 1.0`.
- `AGENTS.md:150` claims `PRAGMA journal_mode=WAL`; that is applied per-connection at `backend/db.py:21`, not as a persisted database property, so the claim is true in effect but not as stated.

## Root cause
The document was written against an earlier schema and not regenerated when `repertoire_studies`, `study_moves`, `drill_reviews`, `is_book_move`, `explanation`, `strategic_idea`, `category`, `study_name` and `created_at` were added by `backend/db.py:75-179`. There is no schema-drift check in the suite.

## Exploit / escalation
1.
